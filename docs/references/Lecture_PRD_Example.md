# PRD: 강의 커뮤니티 웹서비스

## 1. Product Summary

강의를 수강하는 학생들이 강사에게 편리하게 질문하고, 같은 강의를 듣는 학생들과 자유롭게 토론할 수 있는 강의별 소셜 커뮤니티형 웹서비스.

학생은 강의별로 발급된 수업 코드를 입력하여 해당 강의 커뮤니티에 참여할 수 있다. 커뮤니티 내에서 질문과 토론 글을 작성하고, 다른 학생이나 강사가 작성한 게시글과 댓글을 확인할 수 있다.

강사는 여러 강의의 커뮤니티를 하나의 웹서비스에서 관리하며, 학생들의 질문에 답변하거나 공지사항을 전달할 수 있다.

## 2. Target User

### Primary User: 학생

- 강사의 온·오프라인 강의를 수강하는 학생
- 수업 외 시간에도 강사에게 질문하고 싶은 학생
- 같은 강의를 듣는 다른 학생들과 지식 및 의견을 공유하고 싶은 학생

### Secondary User: 강사(관리자)

- 여러 기관 또는 플랫폼에서 강의를 진행하는 강사
- 강의별 질문과 공지사항을 통합하여 관리하고 싶은 강사

## 3. Problem

기존에는 강의의 종류와 제공 기관에 따라 질문할 수 있는 창구가 기관 웹사이트, 강사 이메일, 관리자 연락처 등으로 분산되어 있어 불편함이 존재한다.

학생들은 강의 시간 외에 어떤 경로로 질문해야 하는지 혼란을 겪으며, 강사는 여러 연락 창구를 개별적으로 확인해야 하므로 답변이 늦어지거나 공지사항이 원활하게 전달되지 않는 문제가 발생한다.

또한 학생들의 질문과 답변이 개별 연락 수단에 분산되어 있어 다른 학생들이 기존 답변을 참고하기 어렵고, 같은 질문이 반복되는 문제도 있다.

## 4. Core Value

### 학생

- 수강 중인 강의의 수업 코드를 입력하여 해당 강의 커뮤니티에 참여할 수 있다.
- 강의 커뮤니티에서 자유롭게 질문과 토론 글을 작성할 수 있다.
- 같은 강의를 듣는 학생들의 게시글과 댓글을 열람할 수 있다.
- 다른 학생의 질문에 댓글을 남겨 서로 도움을 주고받을 수 있다.
- 강사가 작성한 공지사항을 한곳에서 확인할 수 있다.

### 강사(관리자)

- 여러 강의의 커뮤니티를 하나의 계정에서 관리할 수 있다.
- 강의별로 학생들이 작성한 질문 및 토론 글을 열람할 수 있다.
- 학생들의 게시글에 댓글로 답변할 수 있다.
- 강의별 공지사항을 작성하여 학생들에게 전달할 수 있다.
- 새로운 강의를 개설하고 수업 코드를 관리할 수 있다.

- 데스크톱과 모바일을 지원하는 반응형 웹 UI

### Later (추후 구현)

- 계정 정보 페이지 및 프로필 수정
- 학생용 전체 강의 목록 페이지
- 환경설정 페이지

- 동일한 학생 계정으로 여러 강의 참여
- 이미지 및 파일 첨부
- 게시글 검색 및 정렬
- 게시글 답변 완료 상태 표시
- 공지사항 상단 고정 기능

### Out of Scope (개발 대상에서 제외)

- AI 챗봇 및 자동 답변

## 6. User Scenario

### Scenario 1. 학생의 회원가입 및 강의 참여

1. 학생이 강의 커뮤니티 웹사이트에 접속한다.
2. 회원가입 버튼을 클릭한다.
3. 이름, 이메일, 비밀번호를 입력하여 계정을 생성한다.
4. 로그인 후 수업 코드 입력 페이지로 이동한다.
5. 강사에게 전달받은 수업 코드를 입력한다.
6. 유효한 수업 코드인 경우 해당 강의 커뮤니티에 참여한다.
7. 강의 메인 페이지에서 게시글 목록을 확인한다.

### Scenario 2. 학생의 질문 작성 및 답변 확인

1. 강의를 듣던 학생이 수업 외 시간에 궁금한 점이 생긴다.
2. 학생이 웹사이트에 로그인한다.
3. 자신이 수강 중인 강의의 메인 페이지로 이동한다.
4. '글 작성' 버튼을 클릭한다.
5. 카테고리에서 '질문'을 선택한다.
6. 제목과 본문을 작성한 후 등록한다.
7. 강사가 해당 질문을 확인하고 댓글로 답변한다.
8. 학생이 다시 웹사이트에 접속하여 자신이 작성한 글을 확인한다.
9. 강사의 답변을 읽고 필요한 경우 추가 댓글을 작성한다.

### Scenario 3. 학생 간 자유토론

1. 학생이 강의 커뮤니티에 접속한다.
2. '자유토론' 카테고리의 게시글을 확인한다.
3. 관심 있는 게시글을 클릭한다.
4. 다른 학생들의 의견을 읽고 댓글을 작성한다.
5. 게시글 작성자 및 다른 학생들이 댓글을 통해 토론을 이어간다.

### Scenario 4. 강사의 강의 개설 및 공지 작성

1. 관리자가 웹사이트에 로그인한다.
2. 관리자 강의 관리 페이지에서 '강의 추가' 버튼을 클릭한다.
3. 강의명을 입력하고 새로운 강의를 생성한다.
4. 시스템이 해당 강의의 고유 수업 코드를 생성한다.
5. 관리자가 코드를 학생들에게 전달한다.
6. 관리자가 해당 강의 커뮤니티에 접속한다.
7. '글 작성' 버튼을 클릭하고 '공지' 카테고리를 선택한다.
8. 공지사항을 작성하여 등록한다.
9. 해당 강의에 참여한 학생들이 공지사항을 확인한다.

## 7. User Flow

### 7.1 학생 인증 및 강의 참여

**웹사이트 접속**

- 로그인 상태인 경우
  - 이미 참여한 강의가 있는 경우 → 강의 메인 페이지로 이동
  - 참여한 강의가 없는 경우 → 수업 코드 입력 페이지로 이동
- 비로그인 상태인 경우 → 랜딩 페이지 표시
  - 아이디, 비밀번호 입력 혹은 소셜 로그인 선택하여 로그인 → 강의 메인 페이지 혹은 수업 코드 입력 페이지
  - 회원가입 선택 → 회원가입 페이지

**회원가입**

1. 이름 입력
2. 이메일 입력
3. 비밀번호 입력
4. 회원가입 버튼 클릭
5. 입력값 유효성 검사
   - 유효함 → 계정 생성
   - 유효하지 않음 → 오류 메시지 표시
6. 가입 완료 후 로그인 상태가 확인되면 수업 코드 입력 페이지로 이동
   - 이메일 인증이 필요한 경우 → 인증 안내 후 로그인

**수업 코드 입력**

1. 수업 코드 입력 페이지 표시
2. 학생이 수업 코드 입력
3. 참여 버튼 클릭
4. 서버에서 코드 유효성 검증
   - 유효한 코드 → 강의 참여 정보 저장 → 강의 메인 페이지
   - 존재하지 않는 코드 → 오류 메시지 표시
   - 이미 참여한 강의 → 기존 강의 메인 페이지로 이동

### 7.2 학생 게시글 탐색 및 작성

**강의 메인 페이지**

- 카테고리 선택
  - 전체 → 조회 가능한 모든 카테고리의 게시글 표시
  - 질문 → 질문 게시글만 표시
  - 자유토론 → 자유토론 게시글만 표시
  - 공지 → 공지사항만 표시

- 게시글 클릭
  1. 게시글 상세 페이지 이동
  2. 게시글 및 댓글 열람
  3. 댓글 입력 및 등록
  4. 본인 댓글인 경우 수정 또는 삭제 가능
  5. 본인 게시글인 경우 수정 또는 삭제 가능
  6. 목록으로 돌아가기 클릭 → 강의 메인 페이지 이동

- 글 작성 버튼 클릭
  1. 게시글 작성 페이지 이동
  2. 카테고리 선택(질문 / 자유토론)
  3. 제목 입력
  4. 본문 입력
  5. 등록 버튼 클릭
     - 정상 입력 → 게시글 저장 → 작성된 게시글 상세 페이지로 이동
     - 필수 항목 누락 → 오류 메시지 표시
  6. 취소 버튼 클릭 → 강의 메인 페이지로 이동

### 7.3 관리자 강의 관리

**관리자 로그인**

1. 이메일과 비밀번호 입력
2. 관리자 권한 확인
3. 관리자 강의 관리 페이지 이동

**강의 관리 페이지**

- 기존 강의 선택 → 해당 강의 메인 페이지 이동
- 강의 추가 버튼 클릭
  1. 강의 추가 화면 표시
  2. 강의명 입력
  3. 생성 버튼 클릭
  4. 강의 데이터 저장
  5. 고유 수업 코드 자동 생성
  6. 강의 목록에 신규 강의 표시
- 강의별 수업 코드 확인 및 복사

**관리자 강의 커뮤니티**

- 질문 및 자유토론 글 확인
- 학생 게시글에 댓글 작성
- 공지사항 작성
- 공지사항 수정 및 삭제
- 부적절한 게시글 및 댓글 삭제
- 강의 관리 페이지로 이동하여 다른 강의 선택

## 8. Screens

### 8.1 랜딩 페이지

**목적:** 서비스 소개 및 회원가입·로그인 유도

**구성 요소**
- 서비스 로고 및 이름
- 서비스 소개 문구
- 로그인 버튼
- 회원가입 버튼

**동작**
- 로그인 버튼 → 로그인 페이지 이동
- 회원가입 버튼 → 회원가입 페이지 이동
- 이미 로그인한 사용자 → 계정 역할 및 강의 참여 상태에 따른 페이지 이동

### 8.2 회원가입 페이지

**목적:** 학생 계정 생성

**구성 요소**
- 이름 입력란
- 이메일 입력란
- 비밀번호 입력란
- 비밀번호 확인 입력란
- 회원가입 버튼
- 로그인 페이지 이동 링크
- 오류 메시지 영역

**동작**
- 필수 항목 입력 여부 확인
- 이메일 형식 검증
- 비밀번호 일치 여부 검증
- 이미 가입된 이메일 처리
- 가입 성공 시 인증 상태에 따라 다음 페이지로 이동

### 8.3 로그인 페이지

**목적:** 기존 사용자 인증

**구성 요소**
- 이메일 입력란
- 비밀번호 입력란
- 로그인 버튼
- 회원가입 페이지 이동 링크
- 오류 메시지 영역

**동작**
- 인증 성공 → 사용자 역할 확인
  - 관리자 → 강의 관리 페이지
  - 학생(강의 참여 완료) → 강의 메인 페이지
  - 학생(강의 미참여) → 수업 코드 입력 페이지
- 인증 실패 → 오류 메시지 표시

### 8.4 수업 코드 입력 페이지

**목적:** 학생의 강의 커뮤니티 참여

**구성 요소**
- 페이지 제목 및 안내 문구
- 수업 코드 입력란
- 참여 버튼
- 오류 메시지 영역
- 로그아웃 버튼

**동작**
- 올바른 코드 입력 → 참여 정보 저장 후 강의 메인 페이지로 이동
- 잘못된 코드 입력 → 오류 메시지 표시
- 빈 입력값 → 입력 안내 메시지 표시

### 8.5 강의별 메인 페이지

**목적:** 강의별 게시글 및 공지사항 탐색

**레이아웃**

**좌측 사이드바**
- 서비스 로고
- 현재 강의명
- 관리자 계정인 경우 '강의 관리' 메뉴
- 로그아웃 버튼

**메인 콘텐츠**
- 강의명 및 페이지 제목
- 카테고리 탭
  - 전체
  - 질문
  - 자유토론
  - 공지
- 게시글 목록
  - 카테고리
  - 제목
  - 작성자
  - 작성일
  - 조회수
- 글 작성 버튼
- 게시글이 없는 경우 빈 화면 안내

**동작**
- 카테고리 선택 → 해당 카테고리 게시글 필터링
- 게시글 클릭 → 게시글 상세 페이지 이동
- 글 작성 버튼 → 게시글 작성 페이지 이동
- 로그아웃 → 로그인 세션 종료 후 랜딩 페이지로 이동

**참고**
- 초기 버전에서는 학생이 하나의 강의에만 참여할 수 있도록 한다.
- 계정 정보, 강의 목록, 강의 추가, 채팅, 환경설정 메뉴는 MVP에서 제외하며 추후 구현한다.
- 관리자에게는 강의 관리 페이지로 돌아갈 수 있는 메뉴를 제공한다.

### 8.6 게시글 작성 및 수정 페이지

**목적:** 게시글 생성 및 수정

**구성 요소**
- 페이지 제목(글 작성 / 글 수정)
- 게시글 제목 입력란
- 카테고리 선택 드롭다운 메뉴
- 본문 작성 입력란
- 등록 또는 수정 완료 버튼
- 취소 버튼

**동작**
- 학생 계정 → 질문 / 자유토론 카테고리 선택 가능
- 관리자 계정 → 질문 / 자유토론 / 공지 카테고리 선택 가능
- 제목 및 본문 필수 입력
- 등록 성공 → 게시글 상세 페이지 이동
- 수정 성공 → 수정된 게시글 상세 페이지 이동
- 취소 → 이전 페이지로 이동
- 다른 사용자의 게시글 수정 불가

### 8.7 게시글 상세 페이지

**목적:** 게시글 열람 및 댓글을 통한 소통

**구성 요소**
- 게시글 카테고리
- 게시글 제목
- 작성자
- 작성일
- 조회수
- 게시글 본문
- 목록으로 돌아가기 버튼
- 게시글 수정 버튼(작성자만)
- 게시글 삭제 버튼(작성자 또는 관리자)
- 댓글 목록
  - 댓글 작성자
  - 댓글 작성일
  - 댓글 내용
  - 댓글 수정 버튼(작성자만)
  - 댓글 삭제 버튼(작성자 또는 관리자)
- 댓글 입력란
- 댓글 등록 버튼

**동작**
- 게시글 상세 열람 시 조회수 증가
- 댓글 등록 → 댓글 목록 갱신
- 댓글 수정 → 수정된 내용 반영
- 삭제 버튼 → 확인창 표시 후 삭제
- 게시글 삭제 완료 → 강의 메인 페이지로 이동
- 댓글 삭제 완료 → 현재 상세 페이지 유지
- 권한에 따라 수정 및 삭제 버튼 표시 여부 결정

### 8.8 관리자 강의 관리 페이지

**목적:** 강의 목록과 수업 코드 통합 관리

**구성 요소**
- 페이지 제목
- 강의 추가 버튼
- 강의 목록
  - 강의명
  - 수업 코드
  - 생성일
  - 강의 커뮤니티 이동 버튼
  - 수업 코드 복사 버튼
- 로그아웃 버튼
- 등록된 강의가 없는 경우 안내 메시지

**동작**
- 강의 선택 → 해당 강의 메인 페이지 이동
- 강의 추가 → 신규 강의 생성
- 수업 코드 복사 → 클립보드에 코드 복사
- 학생 계정은 관리자 강의 관리 페이지에 접근 불가

### 8.9 강의 추가 화면

**목적:** 새로운 강의 개설

**구성 요소**
- 강의명 입력란
- 생성 버튼
- 취소 버튼

**동작**
- 강의명 입력 후 생성 → 고유 수업 코드 자동 발급
- 생성 완료 → 관리자 강의 관리 페이지로 이동
- 강의명 미입력 → 오류 메시지 표시
- 취소 → 관리자 강의 관리 페이지로 이동

## 9. Functional Requirements

### FR-01. 회원가입 및 인증

- 사용자는 이메일과 비밀번호를 이용해 회원가입할 수 있어야 한다.
- 회원가입 시 이름, 이메일, 비밀번호를 필수로 입력해야 한다.
- 이메일은 중복 계정 생성이 불가능해야 한다.
- 비밀번호는 인증 서비스의 보안 정책을 따라야 한다.
- 비밀번호는 애플리케이션 데이터베이스에 평문으로 저장하지 않는다.
- 로그인에 성공하면 인증 세션이 유지되어야 한다.
- 로그아웃 시 인증 세션이 종료되어야 한다.
- 로그인하지 않은 사용자는 강의 커뮤니티에 접근할 수 없어야 한다.

### FR-02. 사용자 역할 및 권한

- 사용자 역할은 `student`와 `admin`으로 구분한다.
- 일반 회원가입으로 생성된 계정의 기본 역할은 `student`로 설정한다.
- 관리자 계정은 시스템에서 사전에 지정한 계정만 사용한다.
- 학생은 관리자 기능에 접근할 수 없어야 한다.
- 학생은 자신이 참여한 강의의 게시글 및 댓글만 조회할 수 있어야 한다.
- 관리자는 자신이 생성하고 관리하는 강의에 접근할 수 있어야 한다.
- 권한 검증은 UI뿐 아니라 데이터베이스 접근 단계에서도 적용해야 한다.

### FR-03. 강의 생성 및 관리

- 관리자는 신규 강의를 생성할 수 있어야 한다.
- 신규 강의 생성 시 강의명을 필수로 입력해야 한다.
- 시스템은 강의 생성 시 고유한 수업 코드를 자동으로 발급해야 한다.
- 수업 코드는 영문 대문자와 숫자를 조합한 8자리 문자열로 생성한다.
- 수업 코드는 시스템 내에서 중복되지 않아야 한다.
- 관리자는 자신이 생성한 강의 목록을 확인할 수 있어야 한다.
- 관리자는 각 강의의 수업 코드를 확인하고 복사할 수 있어야 한다.
- MVP에서는 강의명 수정, 수업 코드 재발급 및 강의 삭제 기능을 제공하지 않는다.

### FR-04. 수업 코드 입력 및 강의 참여

- 학생은 수업 코드를 입력하여 강의에 참여할 수 있어야 한다.
- 시스템은 입력한 코드가 존재하는지 검증해야 한다.
- 유효하지 않은 코드 입력 시 오류 메시지를 표시해야 한다.
- 강의 참여에 성공하면 참여 정보를 데이터베이스에 저장해야 한다.
- 이미 강의에 참여한 학생은 재로그인 시 수업 코드 입력 과정을 생략해야 한다.
- 이미 참여한 강의의 코드를 재입력하는 경우 중복 참여 정보가 생성되지 않아야 한다.
- MVP에서는 학생 계정당 하나의 강의 참여만 허용한다.

### FR-05. 게시글 목록

- 사용자는 접근 권한이 있는 강의의 게시글 목록을 조회할 수 있어야 한다.
- 게시글은 기본적으로 최신 작성순으로 정렬한다.
- 게시글 목록에는 카테고리, 제목, 작성자, 작성일, 조회수를 표시한다.
- 게시글 목록은 카테고리별로 필터링할 수 있어야 한다.
- 학생은 자신이 참여하지 않은 강의의 게시글을 조회할 수 없어야 한다.
- 게시글이 없는 경우 안내 메시지를 표시해야 한다.

### FR-06. 게시글 작성

- 학생은 질문 및 자유토론 카테고리의 게시글을 작성할 수 있어야 한다.
- 관리자는 질문, 자유토론 및 공지 카테고리의 게시글을 작성할 수 있어야 한다.
- 게시글 작성 시 제목과 본문은 필수 입력 항목이다.
- 게시글 생성 시 작성자, 강의, 카테고리, 작성 시간이 함께 저장되어야 한다.
- 게시글 등록 후 해당 게시글의 상세 페이지로 이동해야 한다.
- 학생이 요청 데이터를 임의로 조작하더라도 공지 카테고리의 게시글을 생성할 수 없어야 한다.

### FR-07. 게시글 수정 및 삭제

- 게시글 작성자는 자신이 작성한 글을 수정할 수 있어야 한다.
- 게시글 작성자는 자신이 작성한 글을 삭제할 수 있어야 한다.
- 관리자는 자신이 관리하는 강의의 모든 게시글을 삭제할 수 있어야 한다.
- 관리자는 다른 사용자의 게시글을 수정할 수는 없다.
- 수정 및 삭제 권한은 서버 및 데이터베이스 수준에서도 검증해야 한다.
- 삭제 전 확인창을 표시해야 한다.
- 게시글 삭제 시 해당 게시글에 연결된 댓글도 함께 삭제한다.

### FR-08. 게시글 조회수

- 게시글 상세 페이지에 진입하면 해당 게시글의 조회수가 1 증가해야 한다.
- 게시글 목록 및 상세 페이지에 현재 조회수를 표시해야 한다.
- MVP에서는 동일 사용자의 반복 조회도 각각 조회수에 포함한다.
- 단순 목록 조회는 조회수에 포함하지 않는다.
- 조회수 증가 로직은 중복 요청 및 동시 접근 상황에서도 데이터가 손상되지 않도록 처리한다.

### FR-09. 댓글

- 사용자는 접근 권한이 있는 게시글에 댓글을 작성할 수 있어야 한다.
- 댓글 작성 시 내용은 필수 입력 항목이다.
- 댓글 등록 시 작성자와 작성 시간이 저장되어야 한다.
- 댓글은 기본적으로 작성 시간이 빠른 순서대로 표시한다.
- 댓글 작성자는 자신의 댓글을 수정하고 삭제할 수 있어야 한다.
- 관리자는 자신이 관리하는 강의의 모든 댓글을 삭제할 수 있어야 한다.
- 댓글 삭제 시 확인창을 표시한다.
- MVP에서는 대댓글 및 댓글 좋아요 기능을 제공하지 않는다.

### FR-10. 공지사항

- 공지 카테고리의 게시글은 관리자만 작성할 수 있어야 한다.
- 관리자는 자신이 작성한 공지사항을 수정하거나 삭제할 수 있어야 한다.
- 학생은 공지사항을 열람하고 댓글을 작성할 수 있어야 한다.
- 공지사항은 '공지' 카테고리와 '전체' 카테고리에서 확인할 수 있어야 한다.
- MVP에서는 공지사항 상단 고정 기능을 제공하지 않는다.

### FR-11. 페이지 이동 및 접근 제어

- 로그인하지 않은 사용자가 보호된 페이지에 접근하면 로그인 페이지로 이동해야 한다.
- 학생이 관리자 전용 페이지에 접근하면 접근을 차단해야 한다.
- 학생이 다른 강의의 게시글 URL로 직접 접근하더라도 데이터를 조회할 수 없어야 한다.
- 존재하지 않는 강의 또는 게시글에 접근하면 안내 화면을 표시해야 한다.
- 새로고침 후에도 정상적인 로그인 및 강의 참여 상태가 유지되어야 한다.

### FR-12. 오류 및 상태 처리

- 데이터 요청 중 로딩 상태를 표시해야 한다.
- 서버 오류 및 네트워크 오류 발생 시 사용자에게 안내 메시지를 표시해야 한다.
- 등록·수정·삭제 작업의 성공 또는 실패 결과를 안내해야 한다.
- 게시글이나 댓글이 없는 경우 빈 화면 안내를 표시해야 한다.
- 동일한 작성 요청이 중복 실행되지 않도록 제출 중에는 버튼을 비활성화한다.

## 10. Acceptance Criteria

다음 조건을 모두 충족하면 MVP 개발이 완료된 것으로 판단한다.

### AC-01. 인증

- [ ] 학생이 정상적으로 회원가입할 수 있다.
- [ ] 유효한 계정으로 로그인할 수 있다.
- [ ] 잘못된 로그인 정보 입력 시 오류 메시지가 표시된다.
- [ ] 로그아웃 시 세션이 종료된다.
- [ ] 일반 회원가입으로 관리자 계정을 생성할 수 없다.

### AC-02. 강의 참여

- [ ] 관리자가 강의를 생성할 수 있다.
- [ ] 강의 생성 시 고유 수업 코드가 자동 생성된다.
- [ ] 학생이 유효한 수업 코드로 강의에 참여할 수 있다.
- [ ] 잘못된 코드 입력 시 오류 메시지가 표시된다.
- [ ] 강의 참여 후 다시 로그인해도 참여 정보가 유지된다.
- [ ] 한 학생이 두 개 이상의 강의에 참여할 수 없도록 제한된다.

### AC-03. 게시글

- [ ] 학생이 질문 및 자유토론 글을 작성할 수 있다.
- [ ] 학생이 공지사항을 작성할 수 없다.
- [ ] 관리자가 공지사항을 작성할 수 있다.
- [ ] 게시글 목록이 최신순으로 표시된다.
- [ ] 카테고리별 필터링이 정상적으로 동작한다.
- [ ] 게시글 상세 페이지에서 제목, 본문, 작성자, 조회수가 표시된다.
- [ ] 본인이 작성한 글을 수정하거나 삭제할 수 있다.
- [ ] 다른 학생의 게시글을 수정하거나 삭제할 수 없다.
- [ ] 관리자가 자신이 관리하는 강의의 게시글을 삭제할 수 있다.
- [ ] 게시글 상세 페이지 진입 시 조회수가 증가한다.

### AC-04. 댓글

- [ ] 게시글에 댓글을 작성할 수 있다.
- [ ] 댓글 작성 후 새로고침해도 내용이 유지된다.
- [ ] 본인이 작성한 댓글을 수정하거나 삭제할 수 있다.
- [ ] 다른 학생의 댓글을 수정하거나 삭제할 수 없다.
- [ ] 관리자가 자신이 관리하는 강의의 댓글을 삭제할 수 있다.

### AC-05. 접근 권한

- [ ] 비로그인 사용자는 강의 커뮤니티에 접근할 수 없다.
- [ ] 학생 계정으로 관리자 페이지에 접근할 수 없다.
- [ ] 학생은 참여하지 않은 강의의 게시글과 댓글을 조회할 수 없다.
- [ ] URL을 직접 입력하거나 API 요청을 조작해도 접근 권한을 우회할 수 없다.
- [ ] 관리자는 다른 관리자가 소유한 강의 데이터를 임의로 변경할 수 없다.

### AC-06. UI/UX

- [ ] 주요 페이지가 데스크톱에서 정상적으로 표시된다.
- [ ] 모바일 화면에서도 주요 기능을 사용할 수 있다.
- [ ] 로딩 상태 및 오류 메시지가 정상적으로 표시된다.
- [ ] 게시글 작성부터 강사 답변 확인까지 핵심 시나리오가 정상적으로 동작한다.

## 11. Data Requirements

데이터는 Supabase PostgreSQL에 저장하며, 사용자 인증은 Supabase Auth를 사용한다.

### 11.1 Users / Profiles (사용자 프로필)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | UUID (PK) | Supabase Auth 사용자 ID |
| name | TEXT | 사용자 이름 |
| role | TEXT | student / admin |
| created_at | TIMESTAMPTZ | 계정 생성일 |

**규칙**
- `id`는 Supabase Auth의 사용자 ID를 참조한다.
- 이메일과 인증 비밀번호는 Supabase Auth에서 관리한다.
- `role`의 기본값은 `student`이다.
- `role`은 일반 사용자가 임의로 변경할 수 없어야 한다.

### 11.2 Classes (강의)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | UUID (PK) | 강의 고유 ID |
| title | TEXT | 강의명 |
| class_code | TEXT (UNIQUE) | 강의 참여 코드 |
| admin_id | UUID (FK) | 강의 생성 관리자 ID |
| created_at | TIMESTAMPTZ | 강의 생성일 |

**규칙**
- 각 강의는 고유한 수업 코드를 가진다.
- `admin_id`는 사용자 프로필을 참조한다.
- 수업 코드는 서버 측에서 생성한다.
- 학생에게는 코드 전체 목록을 공개하지 않는다.

### 11.3 Class Members (강의 참여 정보)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | UUID (PK) | 참여 정보 ID |
| class_id | UUID (FK) | 강의 ID |
| user_id | UUID (FK) | 학생 ID |
| joined_at | TIMESTAMPTZ | 참여일 |

**규칙**
- 동일한 학생과 강의 조합은 중복 등록할 수 없다.
- MVP에서는 학생 계정당 하나의 강의 참여만 허용한다.
- 추후 여러 강의 참여 기능을 구현할 수 있도록 별도 테이블로 관리한다.

### 11.4 Posts (게시글)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | UUID (PK) | 게시글 ID |
| class_id | UUID (FK) | 소속 강의 ID |
| author_id | UUID (FK) | 작성자 ID |
| category | TEXT | question / discussion / notice |
| title | TEXT | 게시글 제목 |
| content | TEXT | 게시글 본문 |
| view_count | INTEGER | 조회수(기본값 0) |
| created_at | TIMESTAMPTZ | 작성일 |
| updated_at | TIMESTAMPTZ | 수정일 |

**규칙**
- 게시글은 하나의 강의에 소속된다.
- 학생은 `question`, `discussion` 카테고리만 작성할 수 있다.
- `notice` 카테고리는 관리자만 작성할 수 있다.
- 조회수는 0 이상이어야 한다.
- 작성자 외의 사용자는 게시글을 수정할 수 없다.
- 관리자에게는 자신이 관리하는 강의의 게시글 삭제 권한을 부여한다.

### 11.5 Comments (댓글)

| 필드명 | 타입 | 설명 |
|---|---|---|
| id | UUID (PK) | 댓글 ID |
| post_id | UUID (FK) | 연결 게시글 ID |
| author_id | UUID (FK) | 댓글 작성자 ID |
| content | TEXT | 댓글 내용 |
| created_at | TIMESTAMPTZ | 작성일 |
| updated_at | TIMESTAMPTZ | 수정일 |

**규칙**
- 댓글은 하나의 게시글에 소속된다.
- 댓글 작성자는 자신의 댓글을 수정하고 삭제할 수 있다.
- 관리자는 자신이 관리하는 강의의 댓글을 삭제할 수 있다.
- 게시글 삭제 시 연결된 댓글도 함께 삭제한다.

### 11.6 Data Relationship

- 한 명의 관리자는 여러 강의를 생성할 수 있다.
- 하나의 강의에는 여러 학생이 참여할 수 있다.
- MVP에서는 학생 한 명이 하나의 강의에만 참여한다.
- 하나의 강의에는 여러 게시글이 존재할 수 있다.
- 하나의 게시글에는 여러 댓글이 존재할 수 있다.
- 하나의 사용자는 여러 게시글과 댓글을 작성할 수 있다.

**데이터 관계**

- `Profiles (Admin) 1 : N Classes`
- `Profiles (Student) 1 : 0..1 Class Members`
- `Classes 1 : N Class Members`
- `Classes 1 : N Posts`
- `Profiles 1 : N Posts`
- `Posts 1 : N Comments`
- `Profiles 1 : N Comments`

### 11.7 Data Security

- 모든 사용자 데이터는 Supabase Auth 사용자 ID를 기준으로 연결한다.
- 모든 주요 테이블에 Row Level Security(RLS)를 적용한다.
- 강의별 게시글 및 댓글은 해당 강의의 학생 또는 담당 관리자만 조회할 수 있도록 한다.
- 관리자 역할 부여는 신뢰할 수 있는 서버 측 절차로만 수행한다.
- 강의 참여 여부는 서버 측에서 수업 코드를 검증한 후 저장한다.
- 데이터베이스 직접 접근을 통한 권한 우회를 차단한다.
- 수업 코드는 비밀 인증 수단이 아닌 강의 참여용 코드이며, 로그인 인증을 대체하지 않는다.

## 12. Design Direction

### 12.1 Overall Concept

깔끔하고 직관적인 교육 커뮤니티형 웹서비스.

복잡한 학습관리시스템(LMS)보다는 게시판 중심의 커뮤니티 UI를 지향하며, 학생들이 별도의 사용법을 배우지 않고도 질문을 작성하고 답변을 확인할 수 있도록 한다.

### 12.2 Design Keywords

- Minimal
- Clean
- Modern
- Friendly
- Intuitive
- Community-focused

### 12.3 Layout

**데스크톱**
- 좌측 사이드바와 우측 메인 콘텐츠로 구성
- 사이드바에는 서비스 로고, 현재 강의명, 필수 탐색 메뉴 배치
- 메인 영역 상단에는 강의명과 카테고리 탭 배치
- 게시글 목록을 중심으로 구성
- 주요 행동 버튼(글 작성 등)은 쉽게 찾을 수 있는 위치에 배치

**모바일**
- 반응형 레이아웃 적용
- 좌측 사이드바는 접을 수 있는 메뉴로 전환
- 게시글 목록을 화면 너비에 맞춰 표시
- 주요 버튼과 입력 요소의 터치 영역 확보

### 12.4 Color & Typography

**Color**
- 기본 배경: 화이트 또는 밝은 뉴트럴 계열
- 주요 텍스트: 다크 그레이 또는 블랙
- 보조 텍스트: 그레이
- 주요 액션 버튼: 하나의 일관된 포인트 컬러 사용
- 구분선 및 카드 배경: 연한 그레이 계열

**Typography**
- 한국어 가독성이 높은 산세리프 글꼴 사용
- 예: Pretendard 또는 Noto Sans KR
- 페이지 제목, 게시글 제목, 본문, 보조 정보 간 명확한 시각적 위계 적용

### 12.5 UI Components

- Buttons
- Input Fields
- Textareas
- Dropdown Menus
- Tabs
- Cards
- Modals
- Toast Messages
- Sidebar Navigation
- Empty States
- Loading Indicators

### 12.6 UX Principles

1. **최소한의 단계:** 질문 작성까지 불필요한 페이지 이동을 줄인다.
2. **명확한 탐색:** 사용자가 현재 어떤 강의 커뮤니티에 있는지 쉽게 알 수 있어야 한다.
3. **직관적인 피드백:** 글 등록, 수정, 삭제 등의 작업 결과를 명확하게 표시한다.
4. **일관된 인터페이스:** 학생과 관리자 화면의 공통 요소는 동일한 디자인 규칙을 사용한다.
5. **반응형 설계:** 데스크톱과 모바일 환경 모두에서 핵심 기능을 사용할 수 있어야 한다.
6. **접근성:** 충분한 텍스트 대비, 명확한 입력 레이블, 키보드 조작 및 포커스 표시를 지원한다.

## 13. Technical Stack

### 13.1 Development Tools

| 도구 | 역할 |
|---|---|
| ChatGPT | 아이템 구체화, PRD 작성, 요구사항 정리 |
| Lovable | 초기 웹서비스 및 UI 생성 |
| GitHub | 소스 코드 저장 및 버전 관리 |
| VS Code | 로컬 코드 편집 및 개발 환경 |
| Claude Code | 기능 구현, 코드 수정, 디버깅 |
| Figma | UI/UX 상세 디자인 |
| Figma MCP | Figma 디자인 정보를 Claude Code로 전달 |
| Supabase | 인증, 데이터베이스, 접근 권한 관리 |

### 13.2 Application Stack

- **Frontend:** React + TypeScript
- **Build Tool:** Vite
- **Styling:** Tailwind CSS
- **UI Components:** shadcn/ui (필요에 따라 사용)
- **Backend / BaaS:** Supabase
- **Database:** Supabase PostgreSQL
- **Authentication:** Supabase Auth
- **Authorization:** Supabase Row Level Security(RLS)
- **Version Control:** Git + GitHub

초기 프로젝트 구조는 Lovable에서 생성한 코드를 기준으로 구성하며, 실제 생성된 프로젝트의 의존성과 구조를 확인한 후 유지·조정한다.

### 13.3 Development Workflow

1. ChatGPT에서 PRD 작성 및 기능 요구사항 정의
2. Lovable에서 PRD 기반 초기 웹서비스 생성
3. GitHub 저장소 연결 및 초기 코드 저장(v0)
4. GitHub 저장소를 로컬 환경에 Clone
5. VS Code와 Claude Code를 활용해 Supabase 기능 및 주요 비즈니스 로직 구현
6. 로컬 실행 환경을 통해 UI 확인
7. Figma에서 UI/UX 상세 디자인 및 수정
8. Figma MCP와 Claude Code를 활용해 디자인을 실제 코드에 반영
9. 기능 테스트 및 오류 수정
10. GitHub에 변경 사항 저장(v1)
11. 피드백을 반영하여 반복 개선(v2, v3, ...)

### 13.4 Implementation Guidelines

- 환경변수를 사용하여 Supabase 연결 정보를 관리한다.
- Supabase의 공개용 클라이언트 키와 서버 전용 비밀 키를 구분한다.
- 비밀 키는 브라우저 코드 또는 GitHub 공개 저장소에 포함하지 않는다.
- 로그인 인증과 관리자 권한 검증을 분리한다.
- 관리자 권한을 클라이언트 코드에서 임의로 부여하지 않는다.
- 주요 데이터 접근 정책은 Supabase RLS를 통해 적용한다.
- 조회수 증가와 수업 코드 발급 등 신뢰성이 필요한 로직은 안전한 데이터베이스 함수 또는 서버 측 기능을 활용한다.
- 모든 주요 기능은 실제 Supabase 데이터와 연동한다.
- 개발 초기의 샘플 데이터는 실제 기능 구현 이후 제거하거나 테스트 데이터와 명확히 구분한다.

## 14. Non-goals

이번 MVP의 목적은 **강의별 커뮤니티를 개설하고, 학생들이 질문과 토론에 참여하며, 강사가 댓글과 공지사항을 통해 소통할 수 있는 최소 기능을 구현하는 것**이다.

따라서 다음 사항은 이번 버전의 목표에 포함하지 않는다.

### 14.1 복잡한 학습관리 기능

- 강의 영상 업로드 및 재생
- 학습 진도 관리
- 시험 및 과제 관리
- 성적 산출
- 수료증 발급

### 14.2 고급 커뮤니티 기능

- 실시간 채팅
- 대댓글
- 게시글 좋아요
- 사용자 팔로우
- 게시글 북마크
- 사용자 간 다이렉트 메시지
- 이미지 및 파일 첨부

### 14.3 알림 및 자동화

- 이메일 알림
- 푸시 알림
- 댓글 작성 시 실시간 알림
- AI 기반 질문 자동 응답

### 14.4 고급 계정 및 강의 관리

- 소셜 로그인
- 프로필 이미지 및 상세 프로필 관리
- 학생의 다중 강의 참여
- 강의 삭제 및 수업 코드 재발급
- 강의별 관리자 여러 명 지정
- 학생 초대 이메일 발송
- 관리자 권한을 설정하는 별도 운영자 페이지

### 14.5 기타

- 결제 및 구독 시스템
- 외부 LMS 및 교육 플랫폼 연동
- 모바일 네이티브 앱
- 고급 통계 및 분석 대시보드
- 다국어 지원

이러한 기능은 MVP를 실제로 구현하고 핵심 사용 흐름을 검증한 이후, 필요에 따라 후속 버전에서 검토한다.
