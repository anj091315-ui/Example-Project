# 1. Product Summary
서비스의 목적, 주요 사용자, 핵심 기능, 사용 방식이 드러나도록 제품을 구체적으로 요약.

# 2. Target User
서비스를 사용하는 주요 사용자 그룹을 구분하고, 각 그룹의 특징, 사용 목적 및 필요한 기능을 정의.

# 3. Problem
사용자가 현재 겪고 있는 구체적인 문제와 기존 해결 방식의 한계, 해당 서비스를 통해 해결해야 하는 이유를 설명.

# 4. Core Value
사용자 그룹별로 서비스가 제공하는 핵심 가치와 이를 실현하는 주요 기능 및 기대 효과를 정의.

# 5. MVP Scope
기능을 Must Have(필수 구현), Later(추후 구현), Out of Scope(구현 제외)으로 구분하고, 각 기능의 구체적인 구현 범위와 제한사항을 명시.

# 6. User Scenario
사용자 유형별로 실제 서비스를 사용하는 대표 상황을 설정하고, 사용 목적부터 주요 행동과 최종 결과까지 단계별 시나리오 작성.

# 7. User Flow
사용자가 서비스에 진입한 순간부터 목표를 달성할 때까지의 화면 이동, 사용자 행동, 조건별 분기, 예외 상황 및 처리 결과를 순서대로 정의.

# 8. Screens
서비스에 필요한 모든 화면을 나열하고, 각 화면의 목적, UI 구성 요소, 버튼 및 입력 요소의 기능, 화면 간 이동과 권한별 표시 조건을 정의.

# 9. Functional Requirements
각 기능에 고유 ID를 부여하고, 사용자 행동에 따른 시스템 동작, 입력값 검증, 데이터 처리, 권한 제어 및 오류 처리 규칙을 구체적으로 정의.

# 10. Acceptance Criteria
각 필수 기능의 구현 완료 여부를 객관적으로 검증할 수 있도록 정상 동작, 예외 상황, 권한 및 데이터 처리에 대한 테스트 가능한 체크리스트 작성.

# 11. Data Requirements
서비스 구현에 필요한 데이터 테이블, 각 테이블의 필드명·데이터 타입·설명, 테이블 간 관계, 데이터 유효성 및 저장·접근 권한 규칙을 정의.

# 12. Design Direction
서비스의 디자인 콘셉트, 색상, 타이포그래피, 레이아웃, 주요 UI 컴포넌트, 반응형 디자인 및 사용자 경험 원칙을 구체적으로 정의.

# 13. Technical Stack
Lovable(디자인 초안), GitHub, VS Code, Claude Code, Figma, Supabase를 중심으로 사용할 기술과 도구의 역할, 프론트엔드·백엔드 구성, 데이터베이스 및 인증 방식, 개발·배포 워크플로우를 정의.

# 14. Non-goals
이번 버전에서 구현하지 않을 기능과 개발 범위를 명확히 나열하고, MVP에서 제외하는 이유 및 향후 확장 가능성을 구분.
